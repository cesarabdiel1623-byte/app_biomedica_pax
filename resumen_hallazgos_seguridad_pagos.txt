5 Bloqueos principales antes de producción:
1. Ausencia del código fuente de Edge Functions Deno (create-mp-test-preference, mercado-pago-webhook) y migraciones SQL en el repositorio Git.
2. Inexistencia de un flujo de preferencia de pago productivo que calcule montos reales desde la base de datos a partir de una orden en PostgreSQL.
3. Uso de Deep Links con esquema personalizado (gomedical://payment) sin validación de App Links / Universal Links (HTTPS y assetlinks.json).
4. Necesidad de auditar y verificar bloqueos transaccionales SQL (idempotencia y FOR UPDATE) en la base de datos para prevenir race conditions en webhooks.
5. Necesidad de restringir RLS en la tabla 'orders' para revocar permisos de UPDATE sobre columnas de pago/estado a usuarios autenticados.
